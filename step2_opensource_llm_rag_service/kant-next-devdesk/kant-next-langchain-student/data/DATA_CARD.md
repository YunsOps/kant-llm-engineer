# 제공 자료 안내

## 구성과 출처

| 파일 | 내용 | 성격 |
|---|---|---|
| documents.json | 사내 정책 6개 | KANT NEXT 테스트용 정책 |
| release_documents.json | 정규화한 테스트용 릴리스 3개 | 실제 uv 배포 사실이 아닌 테스트용 사례 |
| keywords.json | 문서별 검색 키워드 | 키워드 검색용 인덱스 |
| cases.json | 검색과 질문 사례 5개 | 기대 문서와 요청 후보를 확인하는 공개 사례 |
| challenge_cases.json | 초안 검토 사례 4개 | 유지, 수정, 담당자 확인 경로의 고정 대역 |

정책 ID는 policy-uv, policy-python, policy-secret, policy-incident, policy-access, policy-support입니다. 과제전형에 제공된 테스트용 정책이며 실제 고객 정보나 기밀은 포함하지 않습니다.

릴리스 3개의 원천 ID는 101, 102, 109입니다. 수집 시각 `2026-09-21T00:00:00Z`도 fixture의 고정 값입니다. URL이 공개 저장소를 가리켜도 본문과 버전은 테스트용 데이터입니다. 실제 최신 버전 확인 자료나 사내 승인 버전으로 사용하지 않습니다.

## 문서 형식

원천 JSON 배열의 문서는 `doc_id`, `title`, `body`, `source_url`, `collected_at`, `category` 여섯 필드입니다. 길이 상한은 ID 100자, 제목 300자, 본문 20,000자, URL 2,048자입니다. 수집 시각은 UTC ISO8601이고 ID와 URL은 중복될 수 없습니다.

검색용 LangChain Document는 body를 page_content에 담고 나머지를 metadata에 보존합니다. 키워드는 별도 인덱스를 읽어 metadata에 복사합니다. 키워드가 없는 가져온 릴리스에는 `uv`, `릴리스`, `release`를 기본값으로 사용합니다. 입력 문서 배열을 직접 바꾸지 않습니다.

질문의 `document_ids`는 후보를 제한합니다. 후보 안에서 키워드 점수가 양수인 문서만 최대 3개 검색합니다. 문서 순서는 동점 처리 기준이므로 제공 자료를 임의로 정렬하지 않습니다. 사례의 기대값을 맞추려고 검색 결과를 하드코딩하지 않습니다.

## 자료의 한계

작은 테스트용 자료라 실제 사내 문서 분포를 대표하지 않습니다. 키워드 검색은 동의어, 띄어쓰기와 오타를 모두 이해하지 못합니다. 사례 통과가 일반적인 검색 품질이나 모델 성능을 보장하지 않습니다. 출처 ID 일치와 답변의 사실 일치는 따로 검토해야 합니다.

모든 고정 사례에는 개인 정보나 실제 API 키가 없습니다. 본인 자료로 교체할 때도 공개 또는 테스트용 문서만 사용하고 민감정보를 넣지 않습니다. 자료를 바꾸면 원래 fixture 자료와 실행 결과를 덮어쓰지 않고 별도로 보관합니다.
